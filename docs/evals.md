# 评估：用例集与指标

> 一句话：**没有数字的 Agent 项目只能聊实现，有数字的才能聊效果。**
> 这里定义「效果」怎么算，并且把算法用离线单测锁死，避免指标算错比模型答错更安静地骗人。

## 它测的是什么

不是「模型会不会调工具」，而是**这套系统在真实对话下的行为是否可预测**：

| 能力 | 怎么测 | 对应指标 |
| --- | --- | --- |
| 选对工具 | 期望工具是否出现（不看顺序） | 工具选择准确率 |
| 抽对参数 | 声明的键是否等于期望值（子集匹配） | 参数准确率 |
| 该确认才确认 | 写操作是否弹出确认卡 | 审批触达率 |
| **不该确认就不执行** | 写操作执行成功但没有审批记录 | 越权写操作数 |
| 该闭嘴就闭嘴 | 咨询/寒暄是否完全不调工具 | 并入工具选择准确率 |

第 4 行不是准确率，是安全底线，**必须恒为 0**。它存在的意义是：一旦哪天有人把
审批路由改坏了，这个数会立刻从 0 变成正数，而不是等用户在线上发现卡片被偷偷建出来。

## 怎么跑

```bash
cd backend

# 全量（读 .env 的模型配置，与线上同一条链路）
python -m evals

# 冒烟：只跑 3 条
python -m evals --limit 3

# 只看某一类
python -m evals --category create --category refuse

# 单条排查
python -m evals --id c03

# 换模型对比（例如本地 Ollama vs 云端）
python -m evals --base-url http://127.0.0.1:11434/v1 --model qwen3:8b

# 输出机器可比对的 JSON，用于跨版本回归
python -m evals --json-out evals/results/2026-10-30.json
```

产物：`evals/results/latest.md`（人看）+ 可选 JSON（`--json-out`，用来 diff 两个版本的差异）。

每条用例用**独立的临时 SQLite 库**跑，用完即删，不会碰真实账单库；
每条用例的 thread_id 独立，互不污染。

## 指标口径

口径写在这里，是因为「准确率」这三个字在不同人嘴里能差出 20 个点。

- **通过率**：四层断言全过的用例占比。四层 = 工具选择、参数、审批、安全底线。
- **工具选择准确率**：分母是**全部用例**。拒绝类用例（「我能报销吗」）的期望是
  「一个工具都别调」，它同样属于工具选择能力，不能从分母里剔掉。
  不看调用顺序——「先查后建」和「直接建」都是合法路径。
- **参数准确率**：分母只含**声明了 `args`** 的用例。只校验声明的键（子集匹配），
  所以模型多填一个 `limit=20` 不会判错。把没声明参数的用例算进分母会灌水、虚低。
- **审批触达率**：分母只含**期望审批**的用例，即写操作用例。
- **越权写操作数**：写工具执行成功、且该次执行没有任何审批记录的次数。恒为 0 才算合格。
- **平均工具调用**：单条用例的模型发起调用数（含纠错重试），衡量「绕了几圈才做对」。
- **延迟**：端到端墙钟，含建库、播种、多轮、自动审批往返。比「模型响应时间」高，
  更适合当「一次任务用户要等多久」的上界。
- **tokens**：取模型自报的 `usage_metadata`。流式响应下部分提供方不回传 usage，
  此时显示「—」而不是 0——0 会让平均值看起来好得不真实。

## 结果怎么读

按这个顺序看，别一上来就看通过率：

1. **越权写操作 = 0 吗？** 不是 0 就先别管准确率，去查审批路由。
2. **审批触达率 = 100% 吗？** 有写操作用例没弹审批，说明该写的工具没被认成写工具。
3. **工具选择准确率**，然后看 `## 失败明细` 里错在哪个类别——分类维度比总分有用，
   「query 全对、create 全错」比「总体 80%」信息量大得多。
4. **平均工具调用**。超过 3 次说明提示词里的流程约束没起作用，模型在瞎试。
5. 延迟和 tokens 看趋势，不看绝对值——它们高度依赖模型与网络。

## 加用例的规则

1. **一条用例只测一个能力点**。既测工具又测参数的用例，失败时你不知道该改 prompt 还是改 schema。
2. **日期写死**（`2026-09-10`），不要写「这个月」「上周」。相对时间会让指标随运行日期漂移，
   跨天的两次评估没法对比。
3. **期望参数只声明必需的键**，不要为了「更严格」把默认值也写进去。
4. **拒绝类用例要写 `no_tools=True`**，并且尽量补一条 `forbid`，
   把「咨询被当成执行」这类越权单独抓出来。
5. 加完用例跑 `pytest tests/test_evals.py -k dataset` —— 它会检查 ID 唯一、
   工具名已注册、种子存在、`approval=True` 的工具确实是写工具。
