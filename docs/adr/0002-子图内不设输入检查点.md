# ADR 0002：领域子图内不设输入检查点，只在 Supervisor 层

- 状态：已接受
- 日期：2026-10-19
- 相关：`backend/app/agent/graph.py`

## 背景

项目有两处 `interrupt`：

- `tool_approval` —— 写工具执行前的人工审批
- `input_checkpoint` —— 轮与轮之间让出输入机会（Codex 风格，执行中可追加任务）

引入领域子图（账单 / 日程 / 搜索）时，需要决定：`input_checkpoint` 是放在
子图内部的每一轮，还是只放在主图（Supervisor）层。

## 决策

**只在主图层设 `input_checkpoint`**；子图内的 `agent → tools → agent` 循环直接跑完，
中途不让出输入机会。审批用的 `tool_approval` 仍然放在子图内部。

## 理由

1. **减少中断次数**。子图内一个「查询 → 建卡」链路通常要跑好几轮，
   每轮都挂起等用户输入会让体验变得很碎——用户明明没有新话要说，却被反复打断。
2. **审批不能在子图外**，否则会旁路 HITL。写工具的审批必须紧贴执行点，
   放在子图内才能保证「子图里发起的任何写操作都经过确认」。
   LangGraph 的 `interrupt` 会全局冒泡到顶层调用者，所以放在子图内不会丢失控制权。
3. **主图层才是路由的地方**。追加输入往往需要重新判定领域
   （比如账单查到一半说「顺便加个日程」），这个决策天然属于 Supervisor。
   因此检查点放在主图，拿到新输入后回 `intent` 重新路由，比在子图里就地处理更合理。

## 代价与替代方案

**代价**：子图执行期间用户无法插入新指令，只能等这一段跑完或等审批。
对于耗时很长的子图流程，这是个真实的延迟。

**已否决的替代方案**：

- *子图内每轮都设检查点*：中断次数翻倍，且子图内没有路由能力，
  新输入只能就地追加，无法切换领域。
- *子图内设检查点但不回 intent*：能减少中断，但「追加输入改变领域」这个能力就没了。

## 验证

`backend/scripts/verify_subgraph_iso.py`（已移至 `scripts/`）验证状态隔离性质；
`backend/tests/test_graph_flow.py` 覆盖检查点与追加输入的行为。
